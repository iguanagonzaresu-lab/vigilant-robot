# AI Output Failure Doctor

AI生成物の失敗を、**証拠 → 失敗分類 → 発生段階 → 原因仮説 → 最小再現 → 修正案 → 検証方法**の順で診断するAgent Skill（v0.1）です。
画像・動画・UI・文章・JSON・生成コードを扱います。美しさの採点や生成ツールではありません。

## 使い方

Skill対応エージェントに登録し、次のように依頼します。

```text
$ai-output-failure-doctor
期待仕様と生成物、前回成功時と今回のログを比較して、失敗原因を調べて。
直接確認できた事実と仮説を分けて。ファイルの修正や再生成はしないで。
```

渡すと役立つ資料：期待仕様／元の依頼、実際の出力、比較対象、関連ログ、
プロンプトの必要部分、モデル・設定・seed、変更内容。秘密値は伏せてください。
すべて揃っていなくても診断できますが、未確認箇所は明記します。

## 診断の特徴

- OBSERVED（直接確認）、REPORTED（申告のみ）、INFERRED（推論）、UNKNOWN（未確認）を区別
- 不具合が確定していても原因まで確定したとは扱わない
- 各原因仮説に支持・反証・確信度・切り分けテストを付ける
- 同じseedで完全再現できるとは限らず、1回の改善で解決を断定しない
- 動画の一部フレームだけで全体の品質を保証しない
- 読み取り中心。無断のファイル修正、API再試行、再生成、アップロードを行わない

## 既存Skillとの違い

| Skill | 主な役割 |
|---|---|
| ai-output-failure-doctor | 複数媒体の失敗原因を証拠付きで診断し、再現と検証を設計 |
| output-regression-doctor | ローカル画像・UIスクショのピクセル差分を計測 |
| video-pipeline-doctor | 動画パイプラインのログ・エラーと再試行可否を診断 |
| batch-video-quality-check | 動画ファイルをFFmpeg等で一括検査 |

他Skillを必須依存にはしません。利用環境にある検査ツールを必要な範囲で使います。

## 構成

- `SKILL.md`：起動条件、診断手順、安全上の制約
- `agents/openai.yaml`：一覧表示用メタデータ
- `templates/diagnosis-report.md`：証拠・原因・検証を分けるレポート
- `examples/`：画像・動画・UI・JSONの架空の使用例
- `tests/`：再現可能な練習用入力と評価基準
- `TEST_REPORT.md`：実施した検証と限界
